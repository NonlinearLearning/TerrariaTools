# 规则目录：编译期生成

> 状态：已收口（2026-09-09）；当前生成目录无 feature 维度，四阶段完整。
>
> 读者：新增规则、维护规则组合或实现规则目录生成器的维护者。
>
> 更新时间：2026-09-09。

## 1. 目标

用 Roslyn incremental source generator 生成 `NLISSN.Rules` 的规则目录和直接 factory，移除组合根中逐条维护的 `new XxxRule()` 列表。

历史上的 `RuleRegistry` 手工维护 Mark、Propagate、Lift、Propose 四个列表。新增具体规则但忘记修改列表时，项目仍可编译，规则却不会进入 `RulePipeline`。当前由 `RulePipelineComposer` 消费生成目录，编译期目录把这个遗漏变成可见的生成器诊断。

generator、注册属性、生成目录和 `RulePipelineComposer` 已接入；本页记录已完成的行为等价验证和仍受外部数据集限制的性能测试边界。

## 2. 已冻结的架构

```text
src/NLISSN.Rule/
    规则契约、注册属性、目录 descriptor

src/NLISSN.Rule/Checker/
    netstandard2.0 Roslyn incremental generator（NLISSN.Rule.Checker）

src/NLISSN.Rules/
    具体规则实现
    生成 public static GeneratedRuleCatalog

src/NLISSN/
    RulePipelineComposer
    按 disabled RuleId 组装当前 RulePipeline
```

生成器只扫描当前 `NLISSN.Rules` compilation：

- 不扫描引用程序集；
- 不扫描插件或外部规则目录；
- 不使用运行时反射、`Assembly.GetTypes`、`Activator.CreateInstance` 或 `DependencyContext`；
- 不编译规则 DAG，规则图仍由现有 `RulePipeline` 逻辑构建。

`src/NLISSN.Rule/` 当前是通过 [`NLISSN.Core.csproj`](../../../src/NLISSN.Core/NLISSN.Core.csproj) 链接编译的契约源码目录，不是独立运行时程序集。generator 不引用 `NLISSN.Core` 或 `NLISSN.Rules`，只使用目标 compilation 的 Roslyn symbols 和稳定 metadata name。

## 3. 规则声明契约

### 3.1 阶段由基类决定

具体规则必须直接或间接继承以下四个阶段基类之一：

```text
RuleDefinitionMark       -> Mark
RuleDefinitionPropagate  -> Propagate
RuleDefinitionLift       -> Lift
RuleDefinitionPropose    -> Propose
```

当前目录中的全部注册规则必须在四个阶段各有至少一个真实的具体规则；阶段由具体规则的基类决定，不能由属性伪造，也不能由 no-op 规则填充。生成器在编译期拒绝缺少阶段的当前目录，组合器只消费通过完整性校验的 generated 目录。

当前目录基线为 `Mark/Propagate/Lift/Propose = 19/12/5/32`，共 `68` 个 factory。

### 3.2 当前阶段排除的规则族

以下四个延期规则族若保留在历史源码或历史测试上下文中，也必须使用 `RuleCatalogIgnore` 或移出当前组合入口；它们不属于当前 generated catalog：

- `UnreachableMethodDeletion`
- `UnreferencedMethodDeletion`
- `UnusedInterfaceImplementationCleanup`
- `InternalOnlyPublicMethodPrivatization`

当前阶段不为这些规则族设计或补造四阶段规则，不保留 Mark + Propose 的 legacy 兼容组合，不生成 no-op Propagate/Lift。

### 3.3 注册标记不携带 feature

注册属性只表示进入当前目录，不重复声明阶段、`RuleId` 或默认状态：

```csharp
[RuleRegistration]
public sealed class AtomicIdentifierNameMarkRule : RuleDefinitionMark
{
}
```

`RuleFeature` 不存在，`DefaultEnabled` 也不存在。四个延期规则族仍由 `RuleCatalogIgnore` 排除，不生成 descriptor、factory 或规则图节点；未来重新纳入必须另行定义真实四阶段基线。

### 3.4 RuleId 是唯一规则身份

`CapabilityId` 已废弃；规则目录、运行时校验、规则图和配置禁用标识均使用迁移后的 `RuleId`。

生成器从规则实现的 `RuleId` 属性提取可编译期解析的字符串，不在注册属性中重复声明。`RuleId` 缺失、为空、重复或无法在编译期解析时，报告生成器 error。

目录 descriptor 的最小形状为：

```csharp
public sealed record RuleRegistration<TStage>(
    string RuleId,
    string TypeName,
    string FullyQualifiedName,
    Func<TStage> Factory)
    where TStage : class, IRuleDefinition;
```

`RuleRegistration<TStage>` 属于 `src/NLISSN.Rule/` 契约边界。它不暴露 Roslyn 类型，也不把 generator 实现泄漏到运行时。

## 4. 生成目录

生成器在 `NLISSN.Rules` 程序集中输出固定的公开类型：

```csharp
namespace NLISSN.Rules;

public static class GeneratedRuleCatalog
{
    public static IReadOnlyList<RuleRegistration<RuleDefinitionMark>> Markers { get; }

    public static IReadOnlyList<RuleRegistration<RuleDefinitionPropagate>> Propagators { get; }

    public static IReadOnlyList<RuleRegistration<RuleDefinitionLift>> Lifters { get; }

    public static IReadOnlyList<RuleRegistration<RuleDefinitionPropose>> Proposers { get; }
}
```

约束：

- 四个列表按阶段强类型化；不使用一个异构 `RuleKind + IRuleDefinition` 列表；
- `GeneratedRuleCatalog` 的全限定名固定为 `NLISSN.Rules.GeneratedRuleCatalog`；同名冲突报告 error；
- 列表公开为 `IReadOnlyList<T>`，生成代码内部使用只读包装；
- factory 直接调用具体规则的可访问无参数构造函数；
- 规则类型可以是 `public` 或 `internal`，只要生成代码能够访问类型和构造函数；
- 四个阶段列表始终生成；当前目录必须在四个列表中各有成员；
- 68 个当前目录规则产生四阶段 descriptor、factory 和运行时节点；
- 目录源代码不依赖 generator 的运行时类型。

生成器只负责发现、校验和发射目录。生成目录的文本顺序不是执行顺序。

## 5. 生成器诊断

### Warning

具体阶段规则没有 `RuleRegistration` 时：

```text
报告 warning
忽略该规则
不生成 factory 和目录项
继续生成其余有效规则
```

规则可以用 `RuleCatalogIgnore` 表达有意排除；有意排除不产生“缺少注册” warning。

### Error

以下问题报告 generator error，并且整个 `GeneratedRuleCatalog` 原子失败，不生成部分目录：

- 目标 compilation 缺少规则契约类型；
- 类型无法归入四个阶段；
- 注册元数据非法或互相矛盾；
- `RuleId` 缺失、为空、无法编译期解析或重复；
- 类型或无参数构造函数对生成代码不可访问；
- 类型为抽象类或开放泛型；
- 固定生成类型名冲突；
- 同一规则的阶段无法确定或目录项本身不完整；
- 当前目录缺少 Mark、Propagate、Lift 或 Propose 中任一阶段，报告 `NLRCG011` 并原子失败。

缺少某阶段是 error。四个列表的“目录完整”含义是：所有被声明并通过校验的具体规则均被正确收录，并且当前目录整体在四个阶段都存在真实规则。

生成器 warning 和 error 都必须能由 `CSharpGeneratorDriver` 测试验证。error 不得退化为“跳过一项后继续生成部分目录”。

## 6. 运行时组合

手工 `RuleRegistry` 已删除，`RulePipelineComposer` 是唯一组合入口；所有规则均来自 `GeneratedRuleCatalog`：

```csharp
RulePipelineComposer.Compose(RuleSelection selection)
```

不保留 `CreateDefaultRules`，也不保留四个延期规则 `bool` 重载或旧名称 facade。

选择对象只包含：

```text
DisabledRuleIds
```

`Compose` 的行为固定为：

1. 直接消费四个 generated catalog 列表，不进行 feature 过滤；
2. 以 `TypeName` 的 ordinal 顺序排序；
3. 同名时以完全限定名（例如 `NLISSN.Rules.Experimental.AtomicRule`）的 ordinal 顺序打破并列；
4. 按禁用 `RuleId` 拆分 active / disabled；
5. active 和 disabled descriptor 都调用 factory；
6. 对选中的全部实例执行 `RuleCatalog` 的 RuleId 非空和 Ordinal 全局唯一校验；
7. 构造包含 active、disabled 四阶段列表的 `RulePipeline`；
8. disabled 规则继续保留在 `RulePipeline` 和规则图声明中，但 `IsEnabled = false`。

factory 每次 `Compose` 都创建新规则实例，不缓存 singleton。任一选中 factory 构造失败时，整个管道组装失败，不返回部分管道。

`Compose` 返回管道和结构化规则选择 warning。未知禁用 `RuleId`：

- 按大小写不敏感去重；
- 每个未知标识产生一个稳定排序的 warning；
- 忽略该标识并继续组装；
- 目录外的标识按未知值处理并产生 warning。

外部 YAML 可以继续保留可读的能力开关作为配置适配层；这些开关必须在上层转换为 `RuleSelection`，不能重新进入 `RulePipelineComposer` 的四个 bool 参数。

## 7. 构建输出和测试

### 构建接线

`src/NLISSN.Rule/Checker/` 使用：

```text
TargetFramework: netstandard2.0
Microsoft.CodeAnalysis.CSharp: 4.14.0
Roslyn 引用：PrivateAssets=all
```

`NLISSN.Rules.csproj` 以 Analyzer-only ProjectReference 引用 generator：

```xml
<ProjectReference
    Include="..\NLISSN.Rule\Checker\NLISSN.Rule.Checker.csproj"
    OutputItemType="Analyzer"
    ReferenceOutputAssembly="false" />
```

编译产物和 generated source 都必须留在 `Build`：

```text
Build/src/
Build/src/obj/NLISSN.Rules/generated/
```

不得把 `bin`、`obj` 或 `.g.cs` 写入 `src`。

### 验证

至少包含两层：

1. `CSharpGeneratorDriver` 测试：合法规则、四阶段输出、缺少注册 warning、`RuleCatalogIgnore`、非法构造、重复 RuleId、固定类型冲突、当前目录缺阶段 `NLRCG011`、error 原子失败和稳定排序。
2. 真实 `NLISSN.Rules` MSBuild 集成测试：Analyzer 接线、Build 输出、68 个 generated factory 和 `NLISSN` 对 `GeneratedRuleCatalog` 的消费。

切换前后必须比较：

- 默认当前目录的四阶段成员集合及顺序；
- 当前目录整体的四阶段存在性；四个延期规则族不产生任何目录产物；
- `RuleId`、规则图节点和边；
- active / disabled 规则声明；
- `RuleCatalog` 校验结果；
- `GetRequiredCapabilities()`；
- decision、evidence、rewrite source 和 per-file diff；
- DOP 1、2、16 的稳定结果。

## 8. 回滚边界

在行为等价证据完成前，不删除手工目录作为回滚点。当前等价证据已完成；出现以下任一回归时停止发布并恢复上一通过版本：

- generator error 或目录缺失；
- 当前目录成员集合、阶段顺序或数量不一致；
- RuleId、disabled 图节点或排序改变；
- 图、decision、evidence、rewrite 或 diff 不等价；
- DOP 结果不稳定。

不使用运行时反射扫描来“补齐”生成目录。
