## 本页回答什么

日志和并发都跨越多个宿主，但安全边界不同：日志必须先过滤再格式化并传播 writer 失败；并发必须限制准入、保持顺序并让调用方看到取消或失败。两者不共享业务调度策略。

## 文本日志链

```text
TextLogEvent
  -> TextLogFilter
  -> TextLogFormatter
  -> bounded Channel
  -> single drain worker
  -> StreamWriter
```

当前实现位于 `src/NLISSN.Infrastructure/Logging/`：`TextLogFilter` 决定事件是否进入 sink，`TextLogFormatter` 生成稳定的单行文本，`TextLogFileSink` 负责有界队列、排空、flush 和释放。过滤必须发生在格式化之前；被过滤事件不计入 `RecordsWritten`。消息、路径、引号、反斜杠和控制字符需要稳定转义，不能让一条事件改变日志行数。

sink 的状态边界是 `Open`、`Draining`、`Completed` 和 `Failed`：

- writer 异常要让当前及排队的 flush completion 失败；
- 失败后新的 Emit/Flush 立即报告相同失败状态；
- 已启动的 drain 必须可等待完，不能用同步 Dispose 和异步 Dispose 互相竞态；
- 同步、异步释放都必须幂等，取消不能伪装成成功写入。

`CommandHost` 把 artifact `RunId` 传给 `RuntimeMeasurementLog`，因此运行日志可以与当前 run 目录关联；日志正文不承载 diff 或 proposal 解释。

## 并发 API

`src/NLISSN.Infrastructure/Concurrency/IConcurrencyPool.cs` 暴露有序选择、CPU-bound 选择、按序提交、两阶段提交、遍历和依赖图调度。`BoundedConcurrencyPool`、`ConcurrencyAdmissionController` 和 `ConcurrencyExecutionPolicy` 负责窗口、准入和最小 telemetry。它们保证：

1. 工作可以并发计算，但结果按输入索引或显式 `readyOrder` 稳定提交。
2. 取消令牌贯穿选择、提交和依赖图；已启动工作按 API 契约排空，未开始工作不应伪造结果。
3. admission budget 约束 CPG 构建、目录分析等共享资源，避免在多个层级各自放大 DOP。
4. 规则 DAG 保留 ready/依赖/失败排空语义；CPG builder 保留重排窗口、稳定物化和记录预算。基础设施不替换这些领域策略。

默认 DOP、线程池设置和 `Dataflow` 选择不能因为新增通用 API 而静默改变。当前迁移顺序仍是 no-op 快路径、提交热循环、依赖预规范化和 DOP 1 直接路径；blocking/async API 拆分必须有独立的契约和性能证据。

## CPG WorkBatch 遥测

NLCPG 的 `CpgWorkBatchExecutor` 在一次构建阶段启动固定数量的长期 worker。worker
从有界 batch channel 连续领取工作，把不可变结果写入有界 reducer channel；共享图、
NodeId、边去重和 `FreezeQueryIndex()` 不在 worker 内完成。fragment 专用入口为
`ExecuteFragmentsAsync`，通用事实结果使用泛型 `ExecuteAsync<TResult>`，避免结果类型
可推断时与可选参数产生 overload 歧义。

每个 batch 的 `CpgWorkBatchPerformanceEvent` 记录 stage、stable order、成本/字节估算、
输出节点/边/fragment bytes、queue wait、worker processing、reducer wait、worker index
和三个峰值水位。`NLCPGBuildMetrics.WorkBatchPerformanceEvents` 保存本次构建的事件，
`ICpgWorkBatchPerformanceEventSink` 是可选的外部接收边界；接收方异常被吞掉，不得改变
构图成功、取消或失败语义。当前原始样本与验证命令见
[CPG WorkBatch 遥测基线](../../benchmarks/cpg-workbatch-baseline.md)。

## 非目标与限制

日志统计不能参与删除决策；并发峰值不能被解释成规则语义；顺序稳定也不等于分析结果安全。没有真实大源码的冷/暖样本时，不能声称吞吐、内存或默认并发度提升。writer 失败、取消、零容量队列和依赖图失败必须分别验证，不以单一成功计数覆盖它们。

- Unit：`tests/NLISSN.UnitTests/Logging/TextLogFilterTests.cs`、`tests/NLISSN.UnitTests/Logging/` 下的 formatter/filter 回归和并发基础组件；
- Host：`tests/NLISSN.HostTests/Logging/TextLogFileSinkTests.cs`，覆盖过滤、控制字符、writer failure、flush 和并发 Dispose；
- 规则/CPG：按 [规则 DAG](规则DAG.md) 和 [最小 CPG 架构](cpg-architecture.md) 比较 DOP 1、2、16 的 stage snapshot、图、decision、rewrite 和 diff；
