# 配置与制品

> 状态：当前设计。
>
> 读者：修改 `nlissn.yml`、配置 schema、artifact 目录或配置失败语义的维护者。
>
> 责任边界：Configuration 负责把文件配置解析成不可变运行配置并准备制品目录，不负责规则注册、分析执行或 diff 正文。
>
> 责任：当前仓库维护者。
>
> 更新时间：2026-08-04。

## 本页回答什么

本页只说明配置从哪里来、怎样被验证、怎样变成一次运行的 artifact 边界。用户入口见 [`docs/quick-start.md`](../../quick-start.md)；规则和分析流程见 [删除规则流水线](deletion-pipeline.md)。

## 当前实现

```text
当前工作目录/nlissn.yml
  -> YamlConfigurationLoader
  -> DTO 与 schema/value diagnostics
  -> AnalysisConfiguration
  -> PrepareRunArtifacts
  -> ConfigurationRunHost
  -> CommandHost
```

主要代码位于 `src/NLISSN.Infrastructure/Configuration/`，包括 `YamlConfigurationLoader.cs`、`AnalysisConfiguration.cs`、`ExecutionSettings.cs`、`RulePolicySettings.cs`、`LoggingSettings.cs`、`ArtifactSettings.cs` 和 `ResolvedConfigurationArtifact.cs`。`src/NLISSN/Hosting/ConfigurationRunHost.cs` 是配置加载后的执行宿主。

## 配置契约

- 可执行程序只接受无参数启动：`src/NLISSN/Program.cs` 会拒绝非空参数。
- 原型只从当前工作目录读取 `nlissn.yml`，不做父目录发现，不引入多文件层叠，也不提供 CLI 或环境变量覆盖。
- 当前 schema 为 `schemaVersion: 2`；未知字段、重复键、未来 schema、类型错误、非法路径和互斥字段必须产生诊断。运行时并发字段的拆分和旧全局字段删除见[运行时并发配置](运行时并发配置.md)。
- 相对路径按 loader 约定解析，解析后的配置保存输入、规则策略、执行、日志和 artifact 设置；调用方不应在后续阶段重新解释原始 YAML。
- `AnalysisConfiguration` 是下游运行时的不可变输入。规则启用、DOP、目录并行、日志 writer、diff/evidence/rewrite-plan 开关等设置先在配置边界收口。

## 制品发布

`PrepareRunArtifacts` 先验证配置并准备同一 run 的输出根，再让 `CommandHost` 发布 resolved configuration、diff、evidence、rewrite plan 和 runtime log。当前 feature 契约把默认运行根记录为 `Build\Result\<runId>`，category 目录和写入开关由 `ArtifactSettings` 控制。

发布必须满足：

1. 显式 `null` 的 nested 节点和“没有提供”能产生不同的稳定诊断。
2. resolved configuration 先写 staging 文件，再在同一卷完成原子发布；失败不能留下可被下一次运行误认的半成品。
3. 同一 `runId` 的竞争预留失败关闭，不能静默覆盖另一轮运行。
4. fingerprint 不把输出路径当作分析语义，并保持字段顺序和集合排序稳定。
5. runtime log 使用 artifact 的 `RunId`，这样日志行可以和本次运行目录关联。

## 非目标与限制

Configuration 不读取规则实现、不编译 CPG、不决定 proposal，也不负责把 diff 写成业务解释。schema 的新增字段必须同步 DTO、解析诊断、resolved artifact、文档和测试；仅修改示例 YAML 不构成契约更新。artifact 的性能、跨版本兼容和远程存储仍需独立 feature 与测量，不从原子发布本身推导收益。

## 验证

配置变更至少覆盖：

- `tests/NLISSN.HostTests/Configuration/YamlConfigurationLoaderTests.cs`：类型、null、未知键、路径、互斥项、artifact 和 run id；
- `tests/NLISSN.ContractTests/Configuration/NlissnSchemaContractTests.cs`：schema 与当前项目布局契约；
- `tests/NLISSN.ContractTests/Architecture/LayoutArchitectureTests.cs`：配置项目和宿主物理边界；
- 无参数启动 smoke：`dotnet run --project .\src\NLISSN\NLISSN.csproj`，工作目录中使用真实 `nlissn.yml`。

并发配置的 focused 验收包括六个命名上限的独立映射、旧字段拒绝以及 CPG budget
不再隐式减半；具体执行顺序见[运行时并发配置实施计划](../../plans/2026-09-22-execution-concurrency-configuration.md)。

验证报告必须分别说明配置诊断、artifact 文件和未执行的真实工程规模测量。相关专题：[运行时基础设施](运行时基础设施.md)、[Rewrite 与 Diff](rewrite-and-diff.md)、[测试策略](testing-strategy.md)。
