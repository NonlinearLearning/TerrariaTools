## 本页回答什么

本页是 `NLISSN.Infrastructure` 的入口和共通契约。配置、制品、日志、并发、缓存与测试组件的具体行为分别写在专题页；本页不复制实现细节，也不把未来能力写成已完成。

## 共通不变量

所有基础设施组件必须保持：

- **确定性**：输入顺序、提交顺序、诊断顺序和 fixture manifest 稳定；
- **有界性**：并发窗口、缓存字节数、日志队列和组合数量有显式上限；
- **失败关闭**：无法证明安全时返回诊断、unknown 或保留结果；
- **可取消且可排空**：调用方取消不破坏已启动工作的收敛契约；
- **可观测但不改语义**：统计、provenance 和 artifact 解释结果，不参与规则判断。

## 模块地图

| 模块 | 当前职责 | 进入专题页 |
| --- | --- | --- |
| `src/NLISSN.Infrastructure/Configuration` | Schema 2 YAML、诊断、路径解析、resolved 配置和 run artifact 预留 | [配置与制品](配置与制品.md) |
| `src/NLISSN.Infrastructure/Logging` | filter、formatter、bounded channel、单 drain worker 和文本落盘 | [日志与并发](日志与并发.md) |
| `src/NLISSN.Infrastructure/Concurrency` | 有序异步选择、依赖图调度、准入预算和最小 telemetry | [日志与并发](日志与并发.md) |
| `src/NLISSN.Infrastructure/Caching` | 弱类型隔离、单飞构造、按字节预算的 LRU 和通用统计 | [缓存边界](缓存边界.md) |
| `src/NLISSN.Infrastructure/Testing` | syntax-valid 组件组合、prerequisite、组合生成和最终 diff contract | [测试组件](测试组件.md) |

这些模块不负责规则注册、Mark -> Propagate -> Lift -> Propose 执行、CPG 提交顺序、删除决策或 diff 正文语义。领域 owner 仍拥有 key、失效、生命周期和业务预算；通用设施不能因为名称相似就跨边界共享状态。

## 运行时位置

```text
nlissn.yml
  -> ConfigurationRunHost
  -> CommandHost
  -> DirectoryAnalysisService / ApplicationService
  -> Core decision and rewrite
  -> Host artifact, diff, log and write-back publication
```

`src/NLISSN/Program.cs` 只把无参数启动交给 `ConfigurationRunHost`。Host 读取配置、准备 artifact、选择单文件或目录入口并发布输出；Application 接收内存中的源码和 Roslyn semantic model，负责分析编排；Infrastructure 只提供被这些边界调用的机制。

当前还有一个物理布局例外：`src/NLISSN.Application/ExecutionRuntime.cs` 的命名空间是 `NLISSN.Core.Pipeline`，Core 项目通过链接项编译它。迁移建议仍是独立任务，不在本页伪装成已完成；证据见 [Application 层审查结果](../../docs/research/2026-08-04-application-layer-review.md)。

## 失败关闭

基础设施遇到未知 schema、越界路径、循环 prerequisite、损坏 artifact、写入失败、未知 CPG 边或预算截断时，必须返回诊断、失败状态或 `unavailable`，不能用空结果冒充“没有问题”。这一原则由配置、日志和测试组件专题分别给出具体证据。

## 验证入口

基础设施改动先按专题页的 focused test 验证，再按 [测试策略](testing-strategy.md) 串行扩大到 Unit、Contract、Host 和必要的 Performance。共享 `Build` 输出要求设置仓库内 `DOTNET_CLI_HOME`，并使用 `-p:UseSharedCompilation=false`；不要把测试退出码单独当成删除安全证明。

当前 feature 状态、完成条件和实际数字以 [`Context/feature_list.json`](../../../Context/feature_list.json) 为准。扩展方向和未测量性能目标留在 `docs/research/` 与 feature 状态记录中，不在本页追加愿景列表。
