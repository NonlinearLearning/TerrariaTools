## 本页回答什么

上一级入口是 [当前设计索引](README.md)；本文负责解释系统边界和一次运行，而不是替代各专题页。

NLISSN 是一个以 Roslyn 事实为边界的 C# 删除分析原型。它把源码分析、规则事实、删除决策和文本改写拆开；无法证明安全的结果保留源码，并通过诊断或 evidence 说明原因。

仓库有两条相邻但独立的执行主线：

| 主线 | 入口项目 | 负责什么 |
| --- | --- | --- |
| 最小 CPG | `src/NLCPG/NLCPG.csproj` | 从 Roslyn syntax、semantic 和 operation facts 构建、冻结、查询并可选持久化 CPG |
| 删除分析 | `src/NLISSN/NLISSN.csproj` | 加载 `nlissn.yml`，创建 compilation，执行 Mark -> Propagate -> Lift -> Propose，并生成决策、改写和制品 |

## 从一次运行开始

生产入口只有零参数路径：

```text
working directory/nlissn.yml
  -> YamlConfigurationLoader
  -> immutable AnalysisConfiguration
  -> ConfigurationRunHost
  -> CommandHost / DirectoryAnalysisService
  -> ApplicationService / RulePipeline
  -> evidence + rewrite plan + diff + optional write-back
```

执行 `dotnet run --project .\src\NLISSN\NLISSN.csproj` 时，`src/NLISSN/Program.cs` 只把控制权交给 `ConfigurationRunHost`；非空参数不是第二套配置入口。`nlissn.yml` 中的路径、规则开关、DOP、artifact 和 replay 约束在进入分析前完成解析与校验。

单文件和目录输入都在 `src/NLISSN/Hosting/` 处理。应用层的规则编排在 `src/NLISSN.Application/Analysis/ApplicationService.cs` 和 `RulePipeline.cs`；阶段运行时契约在物理项目 `src/NLISSN.Rule/` 中，命名空间保持 `NLISSN.Core.Pipeline` 以维持已有 API 和架构测试。

## 稳定边界

```text
Roslyn semantic facts
  -> source marks
  -> propagated facts
  -> structural lifts
  -> decisions
  -> non-overlapping RewriteEdit
  -> rewritten source and rendered diff
```

四条边界决定实现方式：

1. worker 只读取 Roslyn semantic facts；图节点、边、去重和提交顺序在稳定调用线程物化。
2. seed mark 保持原子且不可变；结构删除只能消费阶段事实，不能从一个宽 span 反推安全结论。
3. `&&`、`||`、一元、三元和赋值等表达式拓扑由统一路径解释；terminal boundary 不得被后续 Lift 或 Propose 越过。
4. DOP 改变只能改变执行时机，不能改变 evidence、decision、rewritten source 或 diff 字节。

## Application 层边界

Application 接收已经读入内存的源码、语义模型和 `AnalysisRequestSettings`，负责创建或复用 compilation、构建所需 CPG、编译/执行规则图、聚合结果和调用 rewrite。`DirectoryAnalysisUseCase` 不读取文件；文件枚举、读取、写回、diff 和 artifact 发布仍属于 `src/NLISSN/Hosting/`。

Application 可以依赖 `NLISSN.Core`、`NLCPG`、Roslyn 和受限的 `NL.Concurrency` API，但不应依赖 `NLISSN.Rules` 的具体类型、YAML 配置、日志写入或 artifact 路径。默认规则由 `src/NLISSN/Composition/RuleRegistry.cs` 创建后注入。

当前有一个物理布局例外：`src/NLISSN.Application/ExecutionRuntime.cs` 的命名空间是 `NLISSN.Core.Pipeline`，Application 项目排除该文件，Core 项目通过链接项编译它。该文件可以迁移到 `src/NLISSN.Core/Pipeline/`，但应单独更新项目文件和布局契约测试；本页不把建议写成已完成事实。完整证据见 [Application 层审查结果](../../docs/research/2026-08-04-application-layer-review.md)。

## 当前验证口径

`Context/feature_list.json` 是完成条件和状态的唯一来源；`Context/progress.md` 只保留当前交接事实。非平凡任务从 `pwsh -File .\Miscellaneous\init.ps1` 开始。由于仓库共享 `Build` 输出目录，.NET build 和 test 必须串行执行，并使用 `-p:UseSharedCompilation=false`。

设计页中的“已验证”只表示对应 feature 记录过 build、test、fixture、DOP 或 artifact 证据；没有实测数据的性能判断保持为未验收，不从历史记录推导收益。
