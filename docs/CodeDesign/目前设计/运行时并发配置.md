## 配置接口

`execution` 使用六个必填的正整数：

```yaml
execution:
  directoryMaxDegreeOfParallelism: 4
  cpgMaxDegreeOfParallelism: 12
  groupMaxDegreeOfParallelism: 4
  helperMaxDegreeOfParallelism: 4
  replayMaxDegreeOfParallelism: 4
  maxConcurrentOperations: 8
```

六个字段都属于 Schema 2 的 required 集合，值必须大于等于 1。缺失、零值和负值
必须产生对应字段的独立诊断。旧字段是未知属性，必须被拒绝；不能把旧值复制到
目录、CPG、group、helper、replay 或 admission 中。

以下三个布尔开关继续保留，但它们只控制阶段是否启用并行：

- `directoryParallelism: false` 使用目录串行路径；目录数值配置仍然必填。
- `groupParallelism: false` 让规则组阶段使用 1；启用时使用
  `groupMaxDegreeOfParallelism`。
- `helperParallelism: false` 让 helper 扫描使用串行路径；启用时使用
  `helperMaxDegreeOfParallelism`。

`writeBack`、`skipRewrite`、快速目录路径和日志/制品设置不属于并发上限，不因本设计
改变语义。

## 并发接口映射

| 调度边界 | 唯一配置来源 | 主要使用模块 | 约束 |
| --- | --- | --- | --- |
| 目录文件分析 | `directoryMaxDegreeOfParallelism` | `DirectoryAnalysisUseCase` | 目录池同时调度的文件数 |
| 单文件 CPG builder / CPG lease | `cpgMaxDegreeOfParallelism` | `ApplicationService`、目录分析准入 | 当前 builder 请求的 CPG 并发 |
| 规则 DAG、冲突域、Mark/Lift/Decision | `groupMaxDegreeOfParallelism` | `RuleGraphAnalysisExecutor`、Core rule engines | 受 `groupParallelism` 开关约束 |
| helper 扫描 | `helperMaxDegreeOfParallelism` | `ParameterShrinkAnalyzer` | 受 `helperParallelism` 开关约束 |
| rewrite plan replay | `replayMaxDegreeOfParallelism` | `RewritePlanReplayService` | 只影响 replay 调度 |
| 通用 operation admission | `maxConcurrentOperations` | `AnalysisRuntime` | 只限制 admission，不替代其他上限 |

`RoslynPrototypeExecutionOptions` 对外保存这六个命名值，并提供对应的
`Effective...` 访问器。访问器只为程序化调用把非法值收敛到至少 1；YAML 配置的
合法性必须在 loader 边界完成。`CommandHost` 必须使用命名参数逐项构造 runtime
options，不能用一个 DOP 值通过位置参数传播到其他边界。

## CPG 准入和 WorkBatch 范围

`CpgBuildAdmissionBudget` 只接收总 CPG budget。删除
`CpgBuildAdmissionPolicy`、`FairCapped` 以及 lease/pending request 上的 policy 元数据。

一次 CPG 请求的 granted degree 只受以下因素限制：

1. 请求自身的 degree；
2. 当前总 budget 的可用余量；
3. 取消、失败和释放语义。

当总预算为 12 且请求为 12 时，预算不足以外的逻辑不得把请求自动改成 6。目录池
仍然受 `directoryMaxDegreeOfParallelism` 限制；池中每个 CPG builder 使用
`cpgMaxDegreeOfParallelism`，多个文件共享同一个总 CPG budget。

本设计不删除这些局部接口中的 `MaxDegreeOfParallelism`：

- `NLCPGBuilderOptions.MaxDegreeOfParallelism`；
- 通用 `BoundedConcurrencyPool` / `ConcurrencyWindowOptions` 的局部上限；
- NLCPG 项目导出 worker 的 project-pool 配置。

这些接口属于各自 module 的局部 interface，不能与 NLISSN YAML 的旧全局字段混为一谈。

## 可观测性和身份

resolved configuration 必须只投影六个新字段。runtime log、performance identity 和
相关摘要必须记录实际使用的命名上限，至少能区分 directory、CPG、group、helper、
replay 和 admission 的不同配置。局部 WorkBatch 遥测仍记录它自己的 worker/DOP
数据，不需要改名来迎合 NLISSN 配置。

遥测写入失败不得改变分析结果。配置失败必须在路径解析和运行启动前返回；不能由
运行时 `Math.Max` 或旧字段 fallback 掩盖 YAML 错误。

## 验收边界

本轮实现只要求约 10% 的核心定向测试，优先覆盖：

- YAML 六字段映射、缺失/非法值和旧字段拒绝；
- CPG budget 不再隐式减半；
- `PipelineComponentTests` 中的 runtime DOP 映射；
- 一个 group/helper/replay 或 admission 的边界隔离测试；
- 受影响项目的短 build、`check-harness-consistency.ps1` 和 `git diff --check`。

不在本轮运行完整 Fast、Host、Performance 分层，也不启动 Terraria、Version4 或其他
长时间真实工程测试。完整分层是后续发布验收，不是本设计当前的通过证据。

## 不在范围内

- 不删除 CPG WorkBatch 或 project WorkBatch 的局部并发 API。
- 不修改 project export CLI 的 worker 参数或持久化格式。
- 不把所有并发边界合并成一个 admission 上限。
- 不改变规则语义、CPG 图结构、rewrite 结果或 project export 的文件格式。
