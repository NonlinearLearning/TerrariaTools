# 缓存边界

> 状态：当前设计。
>
> 读者：修改通用 cache、AnalysisRuntime 生命周期或 CPG shard retention 的维护者。
>
> 责任边界：Caching 提供可复用的进程内容器和统计，不决定领域 key、TTL、失效、生命周期或容量预算。
>
> 责任：当前仓库维护者。
>
> 更新时间：2026-08-04。

## 本页回答什么

当前基础设施只有两种通用 cache 原语：按 owner key 隔离的 weak typed registry，以及按调用方 weight 约束的 byte-budget LRU。领域缓存仍由 `AnalysisRuntime`、CPG shard、structure view、slice、Mark snapshot 和规则执行 owner 管理。

## 弱类型 registry

`src/NLISSN.Infrastructure/Caching/WeakTypedCacheRegistry.cs` 中的 `WeakTypedCacheRegistry<TKey>` 使用 `ConditionalWeakTable<TKey, ...>` 保存每个 owner key 的类型字典。每个值按 `TValue` 类型建立 `Lazy<object>`：

1. warm hit 先读取已有 lazy，不创建未使用的候选对象；
2. miss 只创建一个候选 lazy，并用并发字典完成单飞构造；
3. 工厂异常会移除当前 lazy，下次调用仍可重试；
4. key 被回收时，registry 不应把生命周期延长成全局强引用。

该类型解决“同一个 owner key 下复用一个类型值”的容器问题，不定义 compilation 是否应该失效，也不判断某个 CPG 查询是否可以复用。

## Byte-budget LRU

`src/NLISSN.Infrastructure/Caching/ByteBudgetLruCache.cs` 中的 `ByteBudgetLruCache<TKey,TValue>` 只接受调用方给出的 `byteWeight` 和总预算：

- `TryGet` 命中后移动到 MRU，并更新 hit/miss；
- `Set` 对零权重或超过预算的值拒绝写入；
- 替换、驱逐、插入和当前 bytes/entries 都进入 `CacheStatistics`；
- 所有容器状态由内部 gate 保护，`Clear` 不改变领域失效策略。

weight 不是对象真实内存大小的自动测量。调用方必须在同一版本内保持 weight 口径稳定；不能用“缓存命中”直接证明分析语义、图完整性或 rewrite 安全。

## Owner 边界

`AnalysisRuntime` 负责 compilation 和运行 epoch 的复用；`CpgShardQueryResolver` 负责 catalog 查找、源码顺序、取消和 shard I/O，并可以把通用 LRU 用作 retention；structure view、slice query、frozen shard、builder 和规则 cache 保留在各自模块。通用设施不跨 owner 合并 key，也不接管失效或取消。

当 source、profile、schema、规则图或 artifact provenance 变化时，是否失效必须由对应 owner 决定。无法证明 cache entry 仍属于同一输入时扩大失效范围或重新计算，不能把 miss/hit 的区别隐藏成空结果。

## 限制与未测量项

当前 feature 只证明容器契约、生命周期边界和 focused regression；没有同一真实大源码的 cold/warm median、allocation 或 working-set 对比，因此本页不宣称缓存带来性能提升，也不改变默认 DOP。跨进程共享、持久化 cache、TTL 和基于内容的增量失效属于独立设计。

## 验证

- Unit：`tests/NLISSN.UnitTests/Caching/WeakTypedCacheRegistryTests.cs` 覆盖 warm hit 不调用工厂、失败移除和复用；
- Contract：`tests/NLISSN.ContractTests/Architecture/CacheInfrastructureBoundaryTests.cs` 检查 generic cache 依赖和 owner 边界；
- CPG/运行时：按 [CPG 能力边界](cpg-capabilities.md) 检查 shard 查询顺序、取消、frontier 和 unavailable；
- 全量扩大：按 [测试策略](testing-strategy.md) 串行运行 Unit、Contract、Host，并单独记录没有执行的真实规模性能测量。
