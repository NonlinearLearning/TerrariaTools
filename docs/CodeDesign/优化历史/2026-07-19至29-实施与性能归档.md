## 早期优化的保留结论

- `delete-class` 目录 fast path 只能做显式、可观测的候选文件过滤；完整目录语义和被跳过文件数必须保留。
- 方法分片并行用于 Syntax/Operation facts，最终 graph merge 仍按稳定顺序串行提交。节点身份、边集合和规则输出必须跨 DOP 一致。
- Syntax/TypeInfo、CFG、DataFlow 和 callsite 的优化先拆分遥测，再消除已证实的重复 semantic query 或临时分配；没有测量不得改变图模型或并发默认值。
- 查询和 slice 需要明确预算、截断事实和 cache 隔离；缓存的局部结果不能污染完整结果。
- `NodeId` 是冻结图的稳定连接键，不能以非稳定 hash 替换；运行时紧凑表示与重建稳定身份分开处理。

## 性能结论与边界

- 构图并发只适用于独立 Roslyn fact 收集；图、边、去重、分片发布和源序提交保持单一稳定所有者。
- DOP、缓存容量、shard 写并发和目录 I/O 默认值没有因单次或未完成运行而调整。
- 完成构建的 routing sidecar 已有 Contract 验证；`cpg-minimal-routing-catalog` 仍缺同输入 warmed 样本，不能宣称 catalog 时间、磁盘占用或查询延迟收益。
- 查询/overlay、线程池内存、稳定提交、目录 I/O、声明符号查询和 Mark snapshot 的性能验收仍由相应 in-progress feature 管理。
- 真实源运行必须记录预热、wall-clock、分配量、managed heap、working set、并发度和图/规则/rewrite 快照；中断、空间耗尽或资源不足的运行不构成基准证据。
