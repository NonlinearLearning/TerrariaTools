# CPG 五项性能优化执行导航与共同门槛

日期：2026-09-25。交付范围：五份可独立执行的方案与本导航；本轮编写文档，不实施产品优化。

用户要求：需要有力度的优化，代价过大的方案不采用。这里把“力度”落实为消除整段重复工作、减少实际扫描或临时存储，而不是预先承诺 CPU 百分比。

## 1. 执行顺序与成本上限

| 顺序 | 独立执行文档 | 默认采用方向 | 不采用的高成本方向 |
| --- | --- | --- | --- |
| P01 | [DataFlow 候选桶裁剪](2026-09-25-dataflow-candidate-scan-pruning-execution.md) | 有条件跳过 Base；证明后移除 BasePath 查询与建桶 | 自适应求交框架、重排候选、方法内并行 |
| P02 | [DataFlow 计划与序号邻接复用](2026-09-25-dataflow-plan-construction-reuse-execution.md) | 零事实短路、合并前向元数据扫描、方法局部序号邻接 | 重写 Facts/CFG 模型、压平全部子事实、通用图存储改造 |
| P03 | [冻结索引统计与排列复用](2026-09-25-frozen-query-index-construction-reuse-execution.md) | 一次直方图、只读 offsets、稳定排列复用 | 新排序算法、并行冻结、改指纹或边顺序 |
| P04 | [跨过程排序与串行发布优化](2026-09-25-interprocedural-sort-publication-execution.md) | 先测比较成本；合格后使用窗口内字符串排名 | 重做已存在的 PlanIndex、绕过 AddEdge、全局字符串排名体系 |
| P05 | [Builder 缓存锁范围优化](2026-09-25-builder-cache-gate-scope-execution.md) | 先测等待/持锁；只移出可证明独立的 miss 准备工作 | 去锁、拆锁体系、worker 私有缓存与 reducer 合并 |

P01 → P02 串行执行，同文件且后者必须以已验收的前者为基线。P03 独立于二者语义，但测量仍串行。P04/P05 同改 NLCPGBuilder.cs，依次进行。每项独立保留或回退，不打成一个大补丁。正在进行的统一调度内核工作另属一个范围，本组不迁移调度器、不放宽它的门槛。

成本分级是本轮规划约束，不是工作量实测：

- 低成本：一个私有算法块的删除、复用或早返回，沿用已有诊断与契约。
- 中成本：方法局部的数据表示或窗口内排序键改变；必须有净收益测量。
- 高成本：改变公开 API、图身份/合并/预算语义，新增长期共享缓存、同步机制、调度器或通用诊断平台。本组不采用。
- 每项最多一个默认方案和一次局部修正。若需要第二套基础设施来证明第一套有用，停止扩展，提交不采用的证据。

## 3. 各项共同的采纳门槛

以下 10%/5% 等数字是本轮设定的工程决策线，均不是预测或已经测得的收益。

| 门槛 | 必须保存的证据 | 处理 |
| --- | --- | --- |
| 正确性 | 完整规范化节点/边载荷、公开查询的原始枚举顺序、原始候选提交序列、预算与退出原因等价 | 任一失败即回退该小补丁 |
| 机制 | 该分册指定的实际扫描/查找/构造次数下降；不得改计数口径伪造减少 | 未下降就停止，不能靠微小墙钟波动接受 |
| 中成本净收益 | Off 模式下目标阶段中位耗时下降至少 10%，三对样本方向一致；或该阶段实际分配字节下降至少 10%；同时总耗时中位回退不超过 5% | 排名预处理、重复 miss 准备等新增成本全部计入 |
| 内存 | 记录峰值同时存活的数组、窗口保留容量和总分配；新增结构不能把局部节省转为更大的常驻成本 | 有确定的净内存回退则拒绝，不能只看元素宽度 |
| 探针资格 | Detailed 与低开销模式配对校准；开销超过 10% 或无法确定时，细项计时不用于收益判定 | 用 Off 总耗时及独立的结构计数；不能扣掉估算探针时间 |

三对样本只是受控的小批量判定，不声称统计显著性。若抖动跨过决策线，最多另做一轮同规模确认；仍不确定则记录 Inconclusive。低成本、已证明删除冗余的补丁可以保留为结构简化候选，但不得标记性能验收完成；中成本方案不采纳。

默认一次预热、三次正式样本，保留每次输入、次序与原始值。DataFlow 沿用现有 21 次调用的完整批次，每个子进程最多 45 秒、单次最多 5 秒，构建另列；基线/候选两版合计测量上限 90 秒。不得为了完成批次缩减方法预算或跳过慢样本。P03/P04/P05 的新小探针同样各设 45 秒批次上限，并明确哪些时间包含构建或进程启动。

只有新证据支持时才扩展真实 NPC；保留完整绑定上下文、完整方法签名和相同预算。该扩展不属于这五份文档的默认执行批次。

## 4. 基线与候选如何比较

1. 在修改算法前保存完整旧输出与基线 Release 产物（包含依赖、deps/runtimeconfig、环境记录），输出目录唯一且禁止覆盖。
2. 基线与候选只允许目标补丁不同；其余配置、输入、JIT、DOP、预算、诊断模式一致。源码在一次运行中改变则该次作废并保留原因。
3. 优先使用同二进制的临时内部 A/B 接线；不新增公开配置，验收后删除旧路径与开关，再用最终二进制复验。若复制旧算法会明显增加成本，则用两套完整产物交替运行并记录限制。
4. 现有 DataFlow 宿主比较 Off/Coarse/Detailed 的结果，只能证明同一算法的模式等价，不能代替改前/改后等价；必须另外比较两版落盘的完整图和提交序列。
5. 语义 oracle 不排序、不仅比较数量，也不随新实现更新。只允许有据可查地调整真实工作计数，不把被删掉的循环伪计为仍执行。
6. 输出至少区分：结构通过、耗时通过、分配通过、未验证、不采用。探针代码不要永久进入生产热路径。

## 6. 每份执行报告的最低内容

记录 feature ID、采用/不采用的理由、源码与 DLL 身份、每项开关和预算、输入与方法、三对原始样本、完整输出等价结果、计数差、分配/保留容量、探针资格、定向/分层测试结果及未验证边界。以这些证据更新 feature_list；不能把“文档已写完”当作“优化已完成”。
